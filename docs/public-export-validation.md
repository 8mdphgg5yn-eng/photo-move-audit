# 公开真实 Takeout 小样本验证

本文件保留 v0.1.2rc1 的首轮真实样本记录。v0.1.2 稳定版使用同一原包重新执行，结果见 [正式版验证记录](release-validation-0.1.2.md)。

日期：2026-10-22。对象：v0.1.2rc1 已安装的 wheel。两个隔离环境各 8 个场景通过，原始 ZIP 指纹前后一致。本次没有发现需要修改应用代码的问题。

## 样本来源和使用范围

来源是 [Immich 官方仓库讨论 #11500](https://github.com/immich-app/immich/discussions/11500)。发帖人 hockeymachine86 描述 Samsung Galaxy S23 动态照片经 Google Takeout 导入后的播放问题，并于 2024-08-01 公开提供标为 Test Sample 的 [takeout-test.zip](https://github.com/user-attachments/files/16448727/takeout-test.zip) 供复现。

该材料属于第三方公开分享的实际 Takeout 复现小样本：包内含 `Takeout/archive_browser.html`、Google Photos 相册目录、两张 JPEG、两段 MP4、两份媒体 JSON 与一份相册 JSON。我们没有自行操作 Google 账号导出，也没有独立证明它与发帖人的完整图库相同，或证明原始包从未经过裁剪。这里记录“社区公开实际导出复现包”，不称为独立采集的完整用户图库。

发布者明确将附件用于问题复现；本次只在本机测试。未确认附件有允许任意再分发的独立开源许可证，因此分发包不包含原始媒体、附件或变更副本，项目 MIT 许可证也不覆盖这些第三方材料。公开文档仅记录来源、操作、计数和指纹。

| 项目 | 值 |
| --- | --- |
| ZIP 大小 | 12,983,710 字节 |
| ZIP SHA-256 | `e1542f664e82147726531fb99113047227227e206e0e2c706f6357fc8cefcc2c` |
| ZIP 文件条目 | 8 |
| 媒体 | 2 张 JPEG、2 段 MP4，共 12,932,362 字节，4 份不同内容 |
| 其他条目 | 3 份 JSON、1 份 HTML，不进入媒体分母 |
| 独立 ZIP CRC 检查 | 全部通过 |

此前检索到的 GooglePhotosTakeoutHelper 单元测试用的是生成字节或单像素图片，未计入真实导出验收。数字取证资料库的 Android 12 整包约 41.9 GB，本次未下载、未测试，也未将其列为通过证据。

## 核对方法

`scripts/public_export_check.py` 不导入核对器模块，而是独立用 Python 标准库读取 ZIP、计算每个条目的完整 SHA-256，并建立来源与目标的预期内容集合。通过已安装 wheel 的命令行生成报告，再逐项检查完整指纹和文件大小、记录位置、缺失集合、目标独有集合、两侧重复组及副本数、完成状态、报告文件和退出码。

原包只读。所有改名、删减、重复、字节改写和截断操作均在临时副本上进行；核对前后比较副本指纹，每个场景后重算原包指纹。场景副本结束后清理，保留原包、原件清单和核对报告。JSON/HTML 元数据内容没有上传或执行。

两个环境使用同一份 v0.1.2rc1 wheel，工作目录在源码目录之外，并确认导入位置位于隔离环境的 `site-packages`。Python 3.14.8 使用基本安装；Python 3.12.14 使用本机缓存离线安装的 Pillow 12.3.0。

## 验收结果

下列各项在两个环境均通过，共 16 次场景验证。

| 场景 | 独立预期与实际结果 |
| --- | --- |
| 原始 ZIP 对照提取后的媒体目录 | 4 份内容全部匹配，缺失、独有、异常均为 0 |
| 改名及中文、空格目录 | 4 份内容全部匹配 |
| 缺少一张 JPEG | 精确报告该内容缺失 1 份，匹配 3 份 |
| 同名 MP4 中部改写一个字节，保留大小和文件头 | 原内容缺失 1 份，新内容独有 1 份；完整指纹确实覆盖文件中部 |
| 同时删减、改写和增加副本 | 缺失 1、独有 1、目标重复组 1、副本 1；集合与文件位置一致 |
| 空目标目录 | 缺失 4 份，扫描流程完成，退出 1 |
| 将真实媒体副本构造成两个 ZIP，并在两侧设置重复 | 4 份不同内容全部匹配，两侧各 1 个重复组，合计多余副本 2 份 |
| 截断 ZIP 副本 | 记录压缩包错误、扫描未完成，退出 2；没有误报为核对通过 |

构造两分卷使用实际媒体字节，但分卷容器是测试脚本生成的，不能据此宣称 Google 原生多分卷已实测。

Pillow 环境的原包两张 JPEG 均完成校验及首帧解码，两段 MP4 只检查文件头；基本环境四份媒体均标记为文件头检查。中部改写的 MP4 未被认定为解码损坏，本工具通过内容差异识别它，符合既有能力边界。

原始包对照场景单次观察：基本环境约 0.13 秒、峰值 RSS 约 38 MB；Pillow 环境首次约 3.48 秒、峰值 RSS 约 94 MB。两个环境部分同时运行，数值仅作本次执行记录，不是性能基准，不能外推大图库耗时或内存。

## 证据与复现

本机证据目录：`artifacts/public-export-validation/`。

- `originals/immich-discussion-11500-takeout-test.zip`：下载的原件。
- `basic-rc1-r2/result.json`、`images-rc1-r2/result.json`：实际运行环境、各场景结果、代码指纹及原件未变记录。
- 对应目录下的 `original-manifest.json`：8 个条目的独立完整指纹；各场景子目录保留 HTML/JSON 报告。
- `artifacts/stable-validation/release-gate.json`：三项验收汇总，绑定分发包与上述证据。

可使用已下载并匹配上表指纹的原包，在安装 wheel 的隔离环境中复现；输出目录必须不存在。脚本不会下载材料或发布内容。

```sh
python3 scripts/public_export_check.py \
  --archive /path/to/takeout-test.zip \
  --python /path/to/installed-venv/bin/python \
  --output artifacts/public-export-check-new
```

首轮验证脚本因在临时工作目录中使用相对解释器路径而未启动应用。修正为绝对路径，并保留虚拟环境可执行文件的符号链接后，完整重跑通过。该失败属于验证脚本，不计入应用场景失败或成功。

## 发布结论边界

这次补齐的是“至少一个可追溯的实际导出包验证”，三项约定门禁已完成，可进入稳定版发布准备；候选版名称和对外发布状态仍保持不变。大图库、Google 原生多分卷、HEIC/RAW 等其他格式、更多导出年代、其他系统和独立实体电脑仍需扩展验证。视频全程播放、云端导出完整性、相册及拍摄日期保留不属于本工具当前核对结论。
