# Photo Audit：照片搬家后，在本机核对有没有漏文件

我开源了一个照片迁移核对工具：**Photo Audit，照片搬家核对器**。目前已发布 v0.1.2，采用 MIT 许可证。

它解决的是迁移结束后的一个具体问题：来源里的照片和视频，在目标位置都找到了吗？

把照片从旧硬盘复制到新目录，或将 Google Takeout 导出包整理成本地照片目录后，只看文件总数不容易判断是否完整。目标里可能多了重复副本，文件也可能改过名字。Photo Audit 会完整读取媒体文件，计算 SHA-256，再按内容比较来源和目标。

文件改名、换了目录，只要完整内容指纹相同，就能匹配；文件经过压缩、编辑或元数据改写，导致字节内容变化，则会作为不同内容列出。

项目地址：[GitHub 仓库](https://github.com/8mdphgg5yn-eng/photo-move-audit)

下载地址：[v0.1.2 稳定版](https://github.com/8mdphgg5yn-eng/photo-move-audit/releases/tag/v0.1.2)

## 能看到什么结果

| 结果分类 | 含义 |
| --- | --- |
| 目标未找到 | 本次目标扫描中，没有找到与来源内容指纹相同的媒体 |
| 重复内容 | 分别列出来源和目标内部的相同内容副本 |
| 目标多出 | 目标存在、来源没有的内容，可能是新文件，也可能是编辑后的版本 |
| 异常与未完成 | 列出读取错误、部分格式异常，以及停止、超限等未完成情况 |

匹配按内容去重。例如，来源同一内容有三个副本，目标有一个，工具会认为这份内容已经找到，不要求所有副本都保留。如果扫描未完成，“目标未找到”只代表当前已读取范围的结果，需要排除错误或补扫后再判断。

两端都支持目录或 ZIP，也可以比较 ZIP 与目录。ZIP 中的媒体直接读取，不需要为核对额外解压。多个导出 ZIP 可以放在同一目录中交给工具读取，但这不等于它能判断分卷是否已经下载齐全。

核对在本机进行，不需要登录照片服务，不上传照片。工具只读取输入文件，如何补搬或处理重复项由使用者决定；它不会自动删除、移动、重命名或修复原件。

结果可以导出为 HTML 阅读报告或 JSON 完整记录，保留文件位置、大小、内容指纹及实际检查级别，便于后续逐项处理。

## 如何开始使用

需要已经安装 **Python 3.10 或更新版本**。当前主要验证环境是 macOS 上的 Python 3.12.14 和 3.14.8，其他系统仍需扩展验证。

### macOS：下载源码包启动

1. 从 [Release 页面](https://github.com/8mdphgg5yn-eng/photo-move-audit/releases/tag/v0.1.2) 下载 `photo-move-audit-0.1.2-source.zip`，完整解压。
2. 双击解压目录中的 `启动照片核对器.command`，启动本机服务并打开浏览器。终端窗口需要保持开启，使用结束后按 Ctrl+C 停止。
3. 第一次使用，可以先点“用自制样本试一遍”。演示使用生成的色块图片，包含故意设置的缺失、重复和格式异常，便于熟悉结果页面。
4. 核对自己的文件时，选择“来源”和“目标”。来源填写迁移前目录或导出 ZIP，目标填写迁移后的目录或 ZIP；两端不能相同或互相包含。
5. 点击“开始核对”，查看结果并按需保存报告。建议先暂停会持续改写两端文件的同步任务。

也可以在解压目录中打开终端，运行：

```sh
python3 -m photo_audit serve
```

网页只绑定本机地址 `127.0.0.1`。保持服务运行时，刷新页面会恢复最近一次结果，不会重新扫描。关闭服务后内存结果消失，需要保留的报告请另行下载。

### 用 wheel 安装

从同一个 Release 页面下载 `photo_move_audit-0.1.2-py3-none-any.whl`，在它所在的目录运行以下命令。下列路径写法适用于 macOS/Linux：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install --no-index --no-deps photo_move_audit-0.1.2-py3-none-any.whl
.venv/bin/photo-audit serve
```

核心运行只依赖 Python 标准库，基本安装不下载第三方运行依赖，也不捆绑 Python。分发文件包括源码和 wheel，目前没有签名的 macOS `.app` 或一键安装器。

### 命令行核对

在源码目录中也可以直接比较两个位置：

```sh
python3 -m photo_audit check '/path/to/source' '/path/to/target' \
  --html '/path/to/reports/audit.html' \
  --json '/path/to/reports/audit.json'
```

将示例路径替换为实际路径。报告父目录须提前存在，输出位置应在来源和目标目录之外；命令行不会覆盖已有报告。退出码 0 表示在本工具检查范围内扫描完成且未发现缺失或记录的异常，1 表示扫描完成但发现缺失或格式异常，2 表示输入错误、取消或扫描未完成等情况。退出码 0 也不等于所有媒体都能完整播放。

## 检查范围与验证情况

默认会检查部分常见文件头、空文件、读取错误，以及已读取 ZIP 媒体条目的 CRC。运行环境安装了可选依赖 Pillow 时，部分支持的图片格式还会进行校验和首帧解码，报告会记录实际使用的能力。

当前不做视频全程解码，不确认所有动画帧、动态照片配对，也不核对相册、拍摄日期或 EXIF/JSON 元数据是否保留。它按完整字节内容比较，不做视觉相似度判断；未知扩展名和元数据 JSON 不进入媒体核对范围，嵌套 ZIP 不递归打开。

v0.1.2 发布前完成了 48 项单元测试：Pillow 环境全部通过，基本环境通过 46 项，另外两项可选解码测试跳过。另做了原生窗口、干净环境安装、桌面及窄屏浏览器、分页、刷新恢复和报告下载检查。

真实材料验证使用了一个社区公开提供的 Takeout 复现小样本，包含 2 张 JPEG 和 2 段 MP4。两个隔离环境各通过 8 个场景，覆盖改名、缺失、重复、文件中部改写和压缩包截断，原包指纹前后未变。这些结果来自同一台 Mac，尚不能代表大图库、所有导出变体或其他系统的表现。详细记录见 [正式版验证说明](https://github.com/8mdphgg5yn-eng/photo-move-audit/blob/v0.1.2/docs/release-validation-0.1.2.md)。

仅凭本地导出包，无法证明云端已经全部导出。请保留来源和独立备份，不要仅凭核对报告删除云端或原始照片。报告可能包含本机路径，分享前请检查。

## 欢迎试用和反馈

如果你正在整理导出照片、迁移硬盘目录，欢迎先用小范围材料试一遍。尤其希望收到不同导出变体、大图库和跨平台使用方面的反馈。

反馈可提交到 [GitHub Issues](https://github.com/8mdphgg5yn-eng/photo-move-audit/issues)，说明操作系统、Python 版本、输入类型、预期结果、实际结果和复现步骤即可。优先提供自制或脱敏后的最小样本，不必上传个人照片、账号信息或原始完整报告。也欢迎通过 Pull Request 改进代码、测试和文档。
