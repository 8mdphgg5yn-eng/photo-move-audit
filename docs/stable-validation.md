## 本机证据

证据位于项目的 `artifacts/stable-validation/`，不会收入分发包：

- `native-dialog-result.json`：受控的真实窗口操作和返回值，绑定选择模块 SHA-256。
- `final-rc1/`：补齐真实样本之前的历史候选包和安装证据，保留原记录。
- `final-rc1-public-export/installation-result.json`：包含本次文档与复现脚本的候选包、隔离安装、源码 ZIP 启动结果及包哈希。
- `final-rc1-public-export/installed-browser/`：已安装版本的浏览器检查日志、截图和下载报告，仅使用自制样本。
- `final-rc1-public-export/SHA256SUMS`：本次 wheel、sdist、源码 ZIP 的 SHA-256。
- `release-gate.json`：更新后的三项验收状态，绑定真实样本记录、原生窗口记录和最终分发包的哈希；历史状态另存 `release-gate-before-public-export.json`。

真实样本证据另位于 `artifacts/public-export-validation/`。两个实测环境中的应用代码及静态资源与本次 wheel 逐文件指纹一致，原生窗口验证的选择模块也与 wheel 一致。分发安装验证只评价安装这一项；`installation-result.json` 不独立决定稳定版资格，三项状态以汇总门禁为准。

早期构建检查曾因 macOS `/var` 与 `/private/var` 路径别名比较，以及验证脚本未将中断信号传给整个启动进程组而失败；已修正验证脚本并重新执行。它们属于验证工具问题，不计为应用已通过的检查。未受控的弹窗关闭和未成功的快捷键自动化均未计入原生操作通过证据。

## 复现发行验证

需要本机已有 uv、含 setuptools 77 或更新版本的构建 Python。脚本不自动下载工具或运行依赖；输出目录必须不存在，避免覆盖旧证据。

```sh
python3 scripts/release_check.py \
  --output artifacts/release-check-new \
  --build-python /path/to/build/python3 \
  --runtime-python /path/to/runtime/python3
```

可重复传入 `--runtime-python` 验证多个现有解释器。已有 Playwright 和 Chrome/Chromium 时，设置 `PHOTO_AUDIT_PLAYWRIGHT_MODULE`、`PHOTO_AUDIT_BROWSER`，加上 `--browser-check`；此项只对第一个隔离安装运行。系统没有安装这些工具时，不应把未运行记成通过。

## 后续真实图库扩展验收

以下流程已用于公开小样本；用于用户个人图库及更大规模数据时继续沿用。大图库验收仍未开展，不计入本次通过范围。

1. 确认有权用于测试的本机导出包或图库路径，记录材料来源、来源端、目标端和已知问题。原件只读，不上传个人照片或完整报告。
2. 扫描前记录导出包或输入媒体的完整指纹清单；使用独立标准库脚本建立预期内容集合，不调用核对器自身函数生成答案。记录文件数、总量、格式、分卷和异常情况。
3. 使用副本设置可核验的改名、缺失、重复、同名不同内容和中部字节改写场景。逐项比对缺失集合、重复组、目标独有集合及完整/未完成状态，不只比较总数。
4. 完成原始数据核对与副本场景后，重新计算原件指纹，确认未改写输入。记录耗时、内存与误报，明确可覆盖的图库规模和格式。
5. 发现会导致漏报、误报或输入修改的问题先修复并回归。扩展验证的结论只适用于覆盖的规模与格式；需要改变代码时重建全部候选包并重新绑定证据。

即使完成这项，也不等于验证云端导出完整、视频全程解码、相册或日期元数据保留；这些仍受 README 中的能力边界限制。
