# 2026-10-22 测试与修复记录

本次测试仅使用程序生成的媒体、自制 ZIP 和模拟文件变化，没有读取个人图库、访问云端图库或安装新依赖。

## 结论

原有测试重跑通过。扩展测试发现一处文件变化检测遗漏，修复后，两套 Python 环境的回归测试、浏览器流程和独立合成场景检查均按预期通过。当前结果支持继续本地试用，不代表真实云端迁移已经验证。

## 已复现并修复的问题

原逻辑在读取文件时核对文件状态，但在计算指纹后、追加结果前，仍有未复查的时间窗口：

1. 文件被另一个文件原子替换，旧文件句柄的读取结果仍可记录为匹配。
2. 可选图片解码开始前，文件被改写；旧内容指纹和新内容的解码结果可能进入同一记录。

新增的两个回归测试在修复前均失败，显示 `scan_complete=True`，不符合预期。修复后，工具会在追加记录前复查路径当前的设备号、inode、大小、修改时间和状态变更时间。检测到变化时记录 `file_changed`，标记扫描未完成，不把旧指纹加入匹配计数。ZIP 扫描前后的变化检查也使用同一组字段。

这仍不是文件系统快照；文件在完成复查后或扫描结束后发生的变化，不在此保证范围内。

## 独立合成迁移场景

`tests/scenario_check.py` 根据生成时的已知分配规则建立正确答案，再核对工具输出；缺失内容还逐组核对了预期 SHA-256，未用工具结果反推正确答案。

| 指标 | 预期 | 实际 |
| --- | --- | --- |
| 来源媒体条目 | 3100 | 3100 |
| 来源不同内容 | 3000 | 3000 |
| 目标媒体文件 | 2990 | 2990 |
| 已找到来源内容 | 2863 | 2863 |
| 目标未找到 | 137 | 137 |
| 目标独有 | 47 | 47 |
| 两端重复组 | 180 | 180 |
| 两端重复副本 | 180 | 180 |
| 格式异常 | 2 | 2 |

来源包含多个 ZIP 和 3000 个元数据 JSON；JSON 按约定忽略。媒体覆盖改名、不同目录、中文和空格路径、重复、缺失和新增。两端共 6090 个媒体记录，但图片均为小尺寸色块，不能据此推算真实照片库耗时。

含 Pillow 环境本机本轮核对耗时约 0.609 秒。扫描前后用独立指纹和修改时间记录检查输入文件，未观察到输入字节或修改时间变化。该时间包含本机缓存等影响，不是性能基准。

另以每端 64 MiB 的合成字节文件检查完整读取：内容相同时匹配；仅在目标文件中部翻转一个字节后，报告 1 份缺失和 1 份目标独有。文件仅带媒体容器文件头，不是可播放视频，不用于验证视频解码能力。

自制 JPEG、PNG、GIF、WebP、BMP、TIFF 各一份，在两端共 12 个文件上完成校验及首帧解码，无格式异常。样本尺寸为 128×96，不代表相机原片、所有编码变体或动画全帧。
